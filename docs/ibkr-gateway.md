# IB Gateway 行情连接

在 Gateway 或 TWS 中登录盈透，保持 **API → 设置 → 只读 API** 勾选，并仅允许本机连接。WheelDesk 设置选择 IB Gateway，填写地址、端口和非零 Client ID。本机实盘 Gateway 默认 4001，模拟盘通常 4002；以客户端显示为准。TWS 常用 7496/7497。

IB Gateway 是唯一生产行情来源。股票、ETF、期权及 CBOE VIX 指数均通过 Gateway 查询；Yahoo 与 Futu 接入已移除。未配置或未登录时显示连接提示，报价缺失时保留原估值和来源，不切换其他供应商。万亿俱乐部股票列表在设置中手动增删，保存后刷新生效；不查询市值。按用户要求，暂不查询财报日期，也不使用财报筛选或确认条件。

首次访问或浏览器重新加载时立即**全量刷新**，包含标的 IV 和持仓期权价格。手动“刷新行情”和切换主页面使用**轻量刷新**：重新获取股票、ETF、VIX，更新股价指标和策略判断，保留所有持仓期权的价格、来源、质量、报价时间及原有错误状态。LEAPS 列表复用同一连接配置上次全量刷新的 IV、涨跌幅、实际日期与错误信息。PMCC 的覆盖、到期和行权风险仍使用最新标的价格重新计算；期权估值沿用上次数据。轻量刷新不会查询标的 IV、持仓期权合约或报价，也不会重算 Wheel 期权理论估值，历史行情失败的处理路径遵守同一范围。

切换主页面时，距上次请求开始不足 60 秒则复用已有数据，失败请求也计入限流；手动刷新不受这 60 秒限制。所有触发共用请求中的保护，避免并发刷新。请求期间显示“刷新中”并保留缓存数据，失败保留旧值、标注过期并允许手动重试。短暂的行情订阅在查询结束的 finally 中取消，不运行后台行情刷新。报价尝试延迟/实时、收市冻结、延迟冻结；按服务器实际 marketDataType 标注时效。延迟及收市报价可用于估值，不能作为当前可成交价格。未取得交易所时间时只显示获取时间。

整批报价、独立历史行情和 VIX 统计历史同时预取，全量刷新额外预取 IV，底层只读查询最多 6 路并发；相同数据的同时请求共用缓存。全量刷新将股票和持仓期权合并为最多 40 个合约的报价批次；轻量刷新批次只含股票、ETF 和 VIX。获取完整报价后提前结束等待。行情类型切换仍串行，防止一个请求改变另一个请求的实时/延迟类型。前端显式调用 `POST /api/market/refresh?scope=stocks` 或 `?scope=full`，响应 `refresh_scope` 标明本次范围；轻量响应不含新的 IV 数据，前端按标的合并上次完整快照中的 IV。新标的缺少缓存时提示 IV 仅在全量刷新时更新，连接配置变化时不会沿用旧配置的 IV。不传 scope 的 API 调用保留全量刷新以兼容旧客户端。

API 断开后，下次刷新会自动重新连接 Gateway；并发查询共用一次重连，连接失败后至少间隔 5 秒才再次尝试。程序没有后台重连轮询，恢复登录后可手动刷新，或在切换页面且满足 60 秒间隔时自动刷新。如果手机登录造成竞争会话，Gateway 到盈透服务器的连接或行情可能中断（例如 1100 / 10197）；API 重连无法替代 Gateway 的账户登录和二次验证。Gateway 恢复账户连接后，下一次刷新重新提交行情请求，不必重启 WheelDesk。参考：[IBKR 连接状态代码](https://interactivebrokers.github.io/tws-api/message_codes.html)。

LEAPS 股票列表显示实际成交时段（日盘、盘前、盘后或夜盘）及美东成交时间。最后成交时间来自 tick 45 / 延迟 tick 88，获取时间不充当成交时间。夜盘仅在合约的 OVERNIGHT 交易时间内查询该场所；SMART 与 OVERNIGHT 按场所隔离缓存，夜盘不可用时保留最近可用报价并注明。盘后/夜盘涨跌幅相对最新已完成正常时段收盘价计算，缺少基准时不显示涨跌幅。VIX 保持 CBOE 指数来源。

DRAM、SOXX 固定加入 LEAPS 观察列表，复用万亿俱乐部入场规则与共享开仓频率，使用同一个 15% 池、单标的 3% 上限及两个槽位。缺少 MA200 或不足 252 个交易日时不触发信号。已有 ETF Long/Short Call 自动归入 PMCC，保留成本、导入来源及历史车轮记录。

VIX 顶部显示刷新时价格、近 52 周日内最高值和历史收盘分位。分位为窗口内已完成交易日收盘值小于或等于当前值的样本数除以有效样本数；未完成当日收盘不计入样本。窗口或数据不完整时不计算分位；策略判断继续使用原有 VIX 完成日线收盘值。

期权通过合约查询核对标的、类型、实际到期日、行权价、USD、标准交易类别及乘数 100，唯一匹配后使用实际 conId。Long 使用 Bid，Short 使用 Ask。失败保留原价格、来源及时间。股票日线使用 ADJUSTED_LAST，VIX 的 IND/CBOE 合约使用 TRADES；均按常规交易时段、排除当天未完成日线，缓存 1 小时并按连接配置隔离。策略中的 VIX 阈值继续使用最近完成日线收盘，连接测试另显示当前可取得的 VIX 延迟报价。每次刷新清除报价缓存，批量查询结果在该次刷新内复用。

LEAPS 股票列表固定以 QQQ、DRAM、SOXX 开头，再展示设置中维护的个股。列为股票、当前价、日涨跌、RSI14、IV、当前持仓占用、说明。当前价旁用括号显示 `(当前价 / MA200 - 1) × 100%`，悬停查看 MA200 原值；历史不足时显示“（MA200 暂缺）”，不单独展示 MA200 列。说明只列出未满足的入场条件，全部满足时显示“—”。DRAM、SOXX 沿用万亿俱乐部的入场规则和共享限频、预算。列表底部不展示 IV 与交易时段介绍段落。

“当前持仓占用”按同一标的汇总仍持有的 Long LEAPS 成本，括号内为其关联 PMCC 的净现金流（已收 Short Call 权利金减当前买回成本），例如 `$5,000.00（+$300.00）`，与顶部 PMCC 统计口径一致。多组持仓合并展示，不计已关闭 Long、普通现货 Wheel 或未归入 PMCC 的其他期权；没有对应持仓显示 `-`，金额为零时显示零值。该字段仅在全量刷新时生成，轻量刷新保留上次完整快照的金额。

IV 从股票/ETF 标的合约的 `OPTION_IMPLIED_VOLATILITY` 历史日线读取，取每日 `close`（IBKR 定义为该日最后的隐含波动率），不是某张持仓期权的 IV。美股常规交易时段开始前排除当天数据；开盘后优先使用当天，缺失则取最近两个有效交易日，始终标明实际日期。前一日 IV 仍用于计算但不单独展示，箭头旁的变化按 `(最新 IV / 前值 IV - 1) × 100%` 计算，表示相对涨跌幅。仅在全量刷新时重新查询 IV，某只股票 IV 缺失时显示空值与原因，其他行情仍正常显示。

IV 与 VIX 统计历史预取失败时，本次刷新直接复用失败结果，避免展示阶段再次查询并重复等待超时；下次对应范围的刷新会重新尝试。总耗时仍取决于 Gateway 的报价和历史查询响应，轻量刷新省略 IV 与持仓期权工作，不承诺固定延迟。

新上市标的日线不足时，列表仍展示已取得的价格和 IV；RSI14 至少需要 15 条完成日线，MA200 至少需要 200 条。历史不足的标的显示“（MA200 暂缺）”，策略所需的完整历史长度校验继续保留。

连接固定 readonly=True，Client ID 不允许 0，操作入口只允许合约、日线、行情、持仓和连接诊断查询。客户端的 readonly 参数不代替 Gateway 的只读开关，后者需要在客户端设置确认。应用不实现提交、修改、取消委托或行权操作。

每次成功刷新会读取并核对当前持仓数量，返回差异，保留现有账本。当前持仓不能还原历史成交、手续费、现金流水或已实现收益；仍需导入活动报表。后续自动报告同步需另行配置 Flex Web Service。

运行只读诊断：

```bash
env -u SSLKEYLOGFILE .venv/bin/python scripts/check_ibkr_market.py --history --contracts
```

诊断结果取决于账户权限、订阅和当前交易时段。实时请求可能因缺少 API 行情权限返回 10089 或 10091；可用的延迟或收市报价仍可用于按需估值，并会标注实际质量。成功连接不代表所有股票、期权或 IV 的权限都已具备，需要分别检查对应诊断结果。

万亿俱乐部成员由用户维护，财报条件暂已停用，因此不依赖市值基本面或 WSH 财报日历订阅。旧账本内 Yahoo 来源标签只保留为历史报价出处，不代表当前仍调用 Yahoo。
